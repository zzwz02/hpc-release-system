# 手册与发布说明分类

分类服务于读者查找 App，不决定发布资格或芯片支持。权威身份、版本、支持范围来自目标 release 与其产物；手册分类沿用目标 RST 中准确的结构；MACA/X201发布说明的类型与模块按下述数据库规则刷新。这里提供编辑用默认类别，不是完整产品目录。

## MACA / X201发布说明的类型与模块

以指定数据库、目标周期快照中的非空 `type` 为类型依据，结合 `doc_target` 确定模块；旧RST中的类型不能覆盖当前数据库的非空类型。类型为空时，才回查已确认是同一App的其他版本、基线快照和既有文档，保留可追溯分类；仍无依据则说明缺口，不凭名称补类别，也不因此排除发布条目。

- `type=工具` 归入“工具”。
- `doc_target=ai4sci`、明确的模型类型、AI for Science框架或AI框架/工具归入“AI for Science模型与框架”。`doc_target=manual` 不应覆盖明确的模型/AI框架类型，例如MONAI、PhysicsNeMo仍归入AI for Science模块。
- 其余科学计算应用归入“HPC APP”（发布列表对应“科学计算应用”分节）。
- 仅统一同义表述以匹配文档风格，例如 `蛋白质/生物分子模型` → `蛋白质与生物分子模型`、`气象/气候模型` → `气象与气候模型`、`AI框架/工具` → `图学习框架与AI工具`；确认是拼写错误时可将 `Al for Science框架` 统一为 `AI for Science框架`。不要把数据库的宽泛类型擅自细化为未经支持的分类。

数据库后续补齐或修正类型时，同步刷新两份发布列表及本期变更表的模块归属，再按 [release_notes.md](release_notes.md) 排序和合并模块单元格。不要保留基于早期空字段生成的“待确认分类”。

## HPC APP

按实际用途使用：基准测试、材料科学计算、分子模拟、数值计算库与求解器、HPC 框架与工具、CFD 与流体模拟、地球系统模拟、海洋环流模拟、天气预报模拟、物理仿真、量子与高能物理计算、信号处理、密码学与安全计算、可视化。

例如 HPL/HPCG 可沿用基准测试分类，数值库放在数值计算库与求解器；跨领域软件按目标手册介绍的用途判断。不要凭某个软件可以用于某领域，就为它新增没有来源的应用描述。

## AI4Sci

框架、库和基础设施放在框架章节；模型放在模型章节。历史 C500 手册分别为第 5、6 章，实际编辑应按标题核对。

模型按已有内容选择：气象与气候、蛋白质与生物分子、材料科学、分子、基因与组学、医学影像、CFD。只有现有类别无法准确承载新内容时才增加子类，避免为单个版本增加类别。

## 名称与别名

比较条目前同时查看 App ID、官方名称、别名、版本与仓库/分支。空格、下划线和大小写可用于查找候选，不是自动合并证据。`Grid` 等通用名称尤其需要确认身份。

保留现有准确写法；旧名到新名的映射应有数据库别名、历史文档或用户说明支持。名称修正不要暗示新发布，也不要把停止某版本误写成停止整个 App。

类别同义词可统一，例如 `HPC基准测试` → `基准测试`、`HPC框架/工具` → `HPC框架与工具`、`CFD/流体模拟` → `CFD与流体模拟`。采用哪种空格与排版服从目标手册风格。手册、变更表、发布列表使用同一套类别名称，避免分别维护互相冲突的映射。

## 芯片与类别分开

学科分类不能推导芯片支持。每个版本分别从目标周期的支持芯片字段建立映射：X201 版本进入 X201 文档，非 X201 版本进入 MACA 文档，双支持版本可同时进入两边。未知支持范围标记待核实，不猜测归属。
