# AI4Sci 用户手册

用于 `C500_Docs/AI4Sci_User_Guide/source/C500_AI4SciUserGuide_CN.rst` 的“AI For Science 加速库介绍”和“AI For Science 模型集合介绍”两章。数据来源和 App 身份的通用规则见上级 [SKILL.md](../SKILL.md)。

## 每期只做一件事：删除不再在开发者社区发布的 App

- 手册只保留本期在开发者社区发布的 App：决策为 `release`，且快照 `community` 的 `image_count` 或 `pkg_count` 大于 0。
- 手册里已有、但本期不满足这个条件的 App，把它的小节整节删除。包括决策不是 `release` 的（`stopped`、`cicd_only`，或系统里找不到），也包括仍在发布但系统里已不在社区发布的。
- 其他内容一概不动：不新增 App，不调整章节结构和顺序，不改保留条目的文字、命令、安装包文件名和版本号。
- 新增 App 的小节由 Owner 自己加进手册，不从数据库或系统产物生成。
- 保留的 App 不改，但每次都要和系统对比并报告不一致，见下一节。

## 报告保留条目与系统的不一致（每次必做）

保留下来的每个 App，都把手册小节和目标周期快照逐项对比，在交付说明里列出不一致的地方，由 Owner 更新；没有不一致也要说明已对比。只报告，不改手册。

- 对比内容：版本号；安装包文件名和目录名里的版本、Python 版本、操作系统；环境变量；测试命令；社区发布的形态（镜像、二进制包）与手册写的用法是否对应。
- 系统一侧取快照的 `version`、`doc`（`image_usage`、`binary_usage`、`env_setup`）、`test_docs`、`community`，以及 app_info 里社区发布构建的 `python_label`、系统版本。
- 每条写清 App、手册现在怎么写、系统本期是什么。例：PhysicsNeMo 小节的二进制包文件名是 1.0.1 / py310 / ubuntu22.04，系统本期发布的是 2.0.0 / py312 / ubuntu24.04。

## 做法

1. 列出两章下的 App 小节，按 App 身份对应到目标周期快照，取每个 App 的发布决策和社区发布情况；同名多版本时只要有一个版本满足条件就保留。
2. 删除不满足条件的小节：从标题行删到下一个标题之前，不动相邻小节的任何一行。
3. 用 `git diff` 确认这份文件只有删除、没有新增行，删除范围正好是这些小节。
4. 对保留的每个 App 做上一节的对比。

## 验证

用渲染脚本 `--only ai4sci_user_guide` 构建，不带 `--strict`：该手册在已发布文本上就有 `changelog` toctree 无标题的警告。确认没有新增警告，被删小节没有在别处被引用。交付说明列出删除了哪些 App 及各自的决策和社区发布情况，以及保留条目与系统的不一致清单。
