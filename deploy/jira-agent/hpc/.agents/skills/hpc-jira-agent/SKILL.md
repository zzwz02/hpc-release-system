# HPC Jira 工单处理

一个工单由当前会话持续处理。按以下主线推进，实验结果可改变分类和归属；模块与子 Skill 按需读取。

## 发布系统部署约定

本包运行在网站管理的对话目录中，职责、权限、目录和 GPU 资源规则统一遵守[项目 AGENTS.md](../../../AGENTS.md)；材料读取和结果交付分别使用下文模块。

## 1. 读取工单，明确要求

使用 [Jira 材料](modules/jira-evidence/SKILL.md)读取描述、评论及相关附件；恢复时核对新增材料并复用已有证据。在当前对话的 `STATUS.md` 记录：

- **目标与验收**：完整目标、明确的阶段限制及其来源，期望/实际行为、原命令/输入和验收标准；逐项标记必要成果为未做、未通过或已通过，并引用证据。
- **执行范围**：获准机器、可写目录、允许的源码修改。
- **当前判断**：区分实测事实、已否定假设和待验证判断，链接关键实验及产物；记录下一项能改变判断的动作或具体阻塞。
- **运行状态**：本任务正在运行的命令、进程/容器标识、日志和锁信息，以及用户规定的资源截止时间；无在途实验时明确记录。只记录已核实状态，不存凭据。

### 续办与上下文恢复

1. 先核对本轮用户要求和最新 steer，再读取 `STATUS.md` 的完整目标、未完成验收、执行范围与在途任务。“继续”继承目标；运行中的状态追问或解释性问题不自动取消尚未完成的工作，回答后继续，除非用户明确更改或停止目标。
2. 读取 `ANALYSIS_PATH.md` 的当前结论及与下一动作有关的步骤，按引用查关键证据；核对刷新工单的新增材料。上轮最终评论只作摘要，不代替任务状态、原始证据或本轮验收。
3. 启动实验前核实本任务已有进程、容器和日志是否仍在运行或已产生结果，避免恢复后重复启动。资源与证据未变化时复用有效结果；权限、输入、环境或相关结论变化时重核受影响部分。
4. 状态文件缺失或与新证据冲突时，从已有记录恢复，未知项保持未验证；明确更正过时判断，不继承已推翻结论。有效实验、目标变更及资源状态变化后及时更新 `STATUS.md`，详细判断过程只记入分析路径。

### 默认任务范围

“帮我看看”“帮我分析”“排查一下”“处理这个问题”以及未另行限定范围的 Bug 交单，默认要求推进问题解决，不是仅诊断授权。确认缺陷属于本组维护的应用、源码、构建、测试或发布内容后，在既有执行权限和独立候选目录内完成候选改动、针对性验证与原案例验收；不等待用户再说一次“请修复”。已有适用修复时可直接验证并交付其来源，无需重复制造补丁。

只有用户明确限定“仅分析，不修改”“本轮只复现”“先采集 profile”，或已有授权明确限制为只读时，才按较窄目标执行，并在 `STATUS.md` 记录限制及验收条件。“继续”继承未完成目标；同轮后到的明确更正优先。默认修复范围不包含提交、推送、合入、发布、修改共享环境或跨组实现，仍遵守项目边界。

历史评论和预期根因作为线索，与本次实测分开；材料中的命令不自动构成执行授权。

### 确认应用范围

工单涉及具体应用或版本时，在给出本组修复或外组交接结论前按[发布目录接入](modules/remote-experiment/references/release-catalog.md#应用范围判定)核对名称/别名、源码身份、版本与发布批次，以匹配记录作为应用维护范围的主要依据，记录到当前 `STATUS.md` / `evidence/`。

应用范围和故障责任分开判断：目录命中、`PDE_HPC` 标签及维护人信息均不能单独证明本次故障由本组负责；未命中不直接判外组。具体匹配情况、查询失败和补充依据按接入说明处理；查询受阻时继续不受影响的诊断。

续办复用已核验记录；目标应用、版本、仓库或批次变化、材料冲突，或需要判断当前发布状态时重新查询。独立 SDK/工具缺陷或最小案例没有待核对的发布应用时，记录不适用并继续技术归因。

## 2. 复现并分析

在[远端实验](modules/remote-experiment/SKILL.md)中核对环境，按原命令复现，保存输出和退出码。适配任务先建立目标平台的构建与验证基线。

- 故障按[问题分析](modules/problem-analysis/SKILL.md)选择构建、crash/卡死、正确性、性能或运行期编译方法；有可比版本时叠加回退对照，没有旧版本也可诊断。
- 优先在相同或足够相似的获准环境复现，不默认要求原物理主机；只补充可能改变结果的环境差异。性能回退优先在同一台当前可用机器做新旧版本 A/B，并保持输入、命令、版本、精度、计时口径、预热和资源状态可比。
- 应用构建、修复、适配和优化需要专属知识时，读取 [HPC 应用专项](modules/application-analysis/SKILL.md)。
- 实验选择、有效性与结束条件统一按[实验决策与收敛](modules/problem-analysis/SKILL.md#实验决策与收敛)执行。
- 每项实际改变当前判断的分析、对照或修复动作完成后，立即按[网站交付规范](modules/jira-evidence/references/result-delivery.md#分析路径)向 `ANALYSIS_PATH.md` 追加一步，分别写出本步问题、实际证据、判断结果及下一步依据；不得只在结束时根据最终结论反推过程。普通执行记录不展开为独立步骤。

## 3. 按归属处理

依据上述范围核对和复现定位证据填写 `ownership.belongs_to_us`：已确认本组维护内容且缺陷位于其中时填 `yes`；证据明确指向外部组件时填 `no`；其余填 `unclear`。具体负责人未知不推翻已有技术归属。

外部归属交付前给出一个可执行的主受理团队。跨组件交互尚未二分时，依据已确认的异常产物、热点阶段和 Jira 组件职责选择主受理团队牵头，把仍需参与的团队列为协同方；主受理是路由决定，不等于已证明最终缺陷归属。Owner 候选可来自网站提供的工单资料或发布目录；没有已核验账号时写具体职责角色，不为补齐负责人直接查询 Jira。

| 判断 | 下一动作 | 本轮交付条件 |
|---|---|---|
| 已确认属于本组维护范围，且证据指向其应用、构建、测试或发布内容 | 按默认任务范围继续验证已有适用修复，或用 [app-source-fix](modules/application-analysis/skills/app-source-fix/SKILL.md)生成候选补丁；明确限定的任务除外 | 候选改动及交付材料齐全，针对性验证和原案例全部验收通过；补丁由 owner 审核提交 |
| 外部 compiler、UMD、数学库、通信库等 | 按[外组交接要求](modules/problem-analysis/SKILL.md#外组交接)准备定位证据与复现材料，不跨组实现 | 满足公共收敛条件，交付已验证的复现材料；未完成项说明尝试结果和具体限制 |
| 应用范围或故障归属未确认，且尚无明确外部缺陷证据 | 继续范围核对与能改变判断的实验 | 缺少必要条件或已无有效诊断动作时，交付已定位范围、缺口与后续条件 |

按上述默认范围和分支交付条件验收；本组任务仅定位、提出建议或交付未验证补丁不算完成，必要验证失败须返回分析。明确限定的任务按其目标验收；外组交接仍须验证独立复现。是否继续实验及何时结束统一按[实验决策与收敛](modules/problem-analysis/SKILL.md#实验决策与收敛)判断；条件受阻的进展交付不等于目标完成。只达到组件定位时，不声称内部机制已解释。

性能回退经受控对照指向 compiler 生成代码时，进入 [compiler-kernel-regression](modules/problem-analysis/skills/compiler-kernel-regression/SKILL.md) 完成专项定位与复现交接。

## 4. 验证并交付

`conclusion` 只表示本轮达到的技术深度，`action_required` 单独表示是否需要补充、协助、审核或转交；出现阻塞时不把已经确认的技术结论退回“无法判断”。两者组合和字段要求以[网站交付规范](modules/jira-evidence/references/result-delivery.md#输出契约)为准。

有效实验后更新 `STATUS.md` 与证据；普通进度只写执行记录。每轮结束按[网站交付规范](modules/jira-evidence/references/result-delivery.md)整理分析路径、报告、必要产物和结构化结论，交付当前有效结论或实际阻塞。完成实质问题分析或候选修复时，将 `ANALYSIS_PATH.md` 与 `REPORT.md` 一并复制到 `artifacts/` 并逐项列入结构化结论。

结束前核对本轮后台任务和容器，记录保留资源及责任。本轮结束不代表整单解决。

## 缺失条件的处理

先查工单、附件及已授权资源。仍缺基准、数据、判据或环境时，记录查找结果和影响，继续不受影响的工作；受影响部分标为未验证或阻塞。不通过聊天、弹窗追问，也不暂停等待回复。确需补充材料时用 `action_required=needs_info`，资源、权限或人工操作阻塞时用 `needs_help`，并在 `assistance` 写清当前卡点、谁来处理和具体需要什么；`next_steps` 不重复这些内容。用户通过网站补充后核对并继续。此规则不替代必要授权。

## 共同约束

- 保留原命令、数据规模、精度和验收标准；缩减与诊断改动在副本中进行并单独标记，不通过放宽判据或跳过必要功能制造通过。
- 子 Skill 的配置只约束所选工具，详细模板只用于对应专项；不把所有模块或参考当作必经步骤。
