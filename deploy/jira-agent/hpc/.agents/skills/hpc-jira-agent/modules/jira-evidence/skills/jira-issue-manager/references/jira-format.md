# JIRA 评论格式

适用于起草和发布本系统的 JIRA 评论。正文使用 JIRA wiki markup；这里只约定排版，不规定报告栏目、内容长度或处理流程。

- 空行分段。标题使用 `h2. 标题`、`h3. 标题`，不要使用 Markdown 的 `## 标题`。
- 粗体写作 `*重点*`，斜体写作 `_说明_`，不要把 Markdown 的 `**重点**` 当作粗体。
- 无序列表每行以 `* ` 开头；有序列表以 `# ` 开头。保持列表标记后的空格。
- 行内代码使用 `{{symbol}}`，不要使用反引号。与中文、字母或数字相邻时留空格，例如 `设置 {{A=1}} 后重试`。
- 多行命令、代码和日志使用独立行的 `{noformat}` 开始、以另一行 `{noformat}` 结束；需要语法高亮时使用 `{code:python}` 和 `{code}`。不要使用 Markdown 的三反引号围栏。块内命令和日志原样保留。
- 链接使用 `[显示文字|https://example.com/path]`，不要使用 Markdown 的 `[显示文字](URL)`。附件优先使用工具返回的附件 ID 直链，不按同名文件猜测链接。
- 表格表头使用 `||列一||列二||`，数据行使用 `|值一|值二|`。不添加 Markdown 的 `|---|---|` 分隔行；含竖线的复杂日志适合放进代码块。
- 宏必须闭合。不要为排版改动代码、命令、URL 或技术结论；不要额外生成服务端负责添加的署名。

格式示例（复制内部文本作为 JIRA 正文，不复制外层 Markdown 围栏）：

```text
h2. 示例

检查 {{example.py}} 的输出，*保留原始报错*。

* 第一项
* 第二项

{noformat}
python example.py --check
{noformat}

[运行日志|https://example.com/build/123/console]
```

网站 JIRA agent 与 MCP 共用服务端排版函数。当前函数修正行内代码间距，并保留 `{code}` / `{noformat}` 内文本；它不是通用 Markdown 转换器，因此起草时仍须使用上述 JIRA 语法。MCP 发布前处理正文，并在用户名确认弹窗展示处理后的完整正文；发布时仅额外添加系统署名。
