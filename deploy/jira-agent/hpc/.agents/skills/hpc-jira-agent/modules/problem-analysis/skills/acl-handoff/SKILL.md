# ACL 问题采集与交接

本专项补充[外组交接](../../SKILL.md#外组交接)：证据已指向 ACL，或需要围绕明确的 ACL 候选采集验证材料时使用。ACL 在这里指数学库/算子团队，不是访问控制。仅出现 BLAS、DNN、FlashAttn、Triton 等名字不能证明归属；先核对应用调用、输入、同步与受控对照。候选阶段沿用现有诊断方法，不提前宣布 ACL 缺陷。

只准备本轮任务所需的材料和建议字段，不直接查询、创建、修改 Jira，也不修改 ACL 内部实现。性能优化和 Feature 模板用于已授权需求或当前故障暴露出的需求缺口，不自动扩大原任务。部署边界和缺失条件处理沿用[主流程](../../../../SKILL.md)。

## 选择模板与采集项

先读[提单字段与材料](references/ticket-templates.md)，确定本次类型与适用项：

| 实际需求 | 建议 Issue Type | 额外处理 |
|---|---|---|
| crash、hang、trap、结果/精度错误等缺陷 | Bug | 同步诊断全日志；按症状补 dump、最小复现 |
| 有可比正常基线、已证实的性能回退 | Bug | 正常/异常 profiling，明确 ACL 算子对回退的贡献 |
| 普通性能不达标或希望提高性能，没有回退证据 | Improvement | 整网与库级对比、目标/ETA、shape、相关附件 |
| 缺少 API 或能力支持 | Feature | 需求、API 语义、验收和 ETA；说明与组件方沟通情况 |

在性能类中，Triton 优化叠加[专项要求](references/triton-gemm.md#triton-优化)，GEMM 优化叠加[专项要求](references/triton-gemm.md#gemm-性能)；两者同时涉及则组合。性能回退仍是 Bug，不能因使用 Triton/GEMM 而改为 Improvement。未证实回退时保留“疑似回退”，继续对照，不把普通性能诉求写成已确认 Bug。

## 执行采集

1. 从网站快照、附件、当前环境和已有实测中复用可用材料；记录原命令、版本、输入/shape、dtype、布局、batch size、训练/推理阶段及计时区间。按模板列出适用项，标记“已取得 / 待补充 / 不适用（理由）”，不能用空表冒充完成。
2. 需要组件日志时按[日志采集](references/log-collection.md)只开启相关组件，保留 stdout、stderr、退出码及生成的 YAML。在获准执行机的任务目录运行，沿用资源锁规则。原始复现、同步诊断、shape 采集、profiling 和正常性能计时分别标识；诊断开关不能污染正式性能数据。
3. 普通性能优化按模板收集目标平台与 A100（或任务约定平台）数据，保持工作量、参数和统计口径可比；性能回退以正常/异常版本对照为核心，只有任务同时要求跨平台比较时才补 A100。所需对照缺少获准机器或现成数据时，继续当前平台可做的工作，明确缺失数据及来源请求，不擅自换机或捏造百分比。
4. 根据组件补齐 selector YAML、FlashAttn YAML、FFT 脚本、Triton 单测/config 或 mctlass shape/调用次数。具体适用条件见参考文件；不要求无关组件日志。仍有可执行的必要采集或独立复现验证时继续，不以“已定位 ACL”结束。

## 交付内容

除公共报告与分析路径外，在当前对话生成：

- `artifacts/ACL_HANDOFF.md`：建议 Jira 字段、选中模板的 Description、归属证据、复现方式、原始性能与计算口径、交付方式/ETA，以及附件说明。沿用模板字段填写实际事实；未知值写“待补充”并解释，不凭模板中的默认人名认定当前 owner。
- `artifacts/ACL_MATERIALS.md`：逐项登记材料状态。列为“要求项 / 适用理由 / 状态 / 本地文件或原始来源 / 缺口、影响与补充人”。区分本轮实测、网站提供和历史引用；只有文件实际存在且对应当前案例才标为已取得。
- 本次真实产生的日志、YAML、dump、单测/最小复现、对比表等具体文件。保留采集命令、运行条件、退出码和文件与案例的映射；不列未生成的附件。

执行[网站交付规范](../../../jira-evidence/references/result-delivery.md)：远端文件先回收，`artifacts` 逐文件列举，不增加 ACL 专用 JSON 顶层字段。网站每文件上限 10 MiB；大日志可无损压缩或分卷，每卷均需符合限制并说明重组方法、原文件大小和摘要。完整日志仍无法交付时，说明保存位置、缺失的完整附件和补取方式；片段不等于模板要求的全日志，不宣称材料齐全。agent 不直接上传 Jira，报告说明由 owner 将适用材料附到目标单。

材料缺口不抹去已证实的技术结论。缺日志/环境信息与缺权限/执行资源分别按主流程记录 `needs_info` / `needs_help` 及具体 `assistance`；状态组合以网站契约为准。仅缺非阻塞元信息时可随交接列明待补项，不为补填表格重复跑实验。满足公共收敛和交接要求后使用 `needs_handoff`，主受理方写 ACL 对应组件团队；协同方、未验证范围和未完成材料明确写进报告。Feature 草稿不冒充缺陷定位或已具备 Bug 转交证据。

简短评论说明定位结果、材料入口和实际待办；完整提单模板放文件，不把整份检查表塞进评论。
