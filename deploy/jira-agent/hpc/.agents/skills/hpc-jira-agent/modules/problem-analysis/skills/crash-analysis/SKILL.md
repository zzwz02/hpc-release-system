# Crash 与执行中断分析

先区分现象：信号/异常退出、程序主动报错、外部终止/OOM、设备错误、无进展等待，或仅运行较慢。保留原命令、输入、退出状态、故障时间和已有日志；单个非零退出码或超时不足以判断根因。

## 按证据推进

- **崩溃**：优先读取本任务已有 core、异常日志和匹配版本的二进制/符号。核对所有相关线程的栈、实际加载库及首个错误；缺符号时标明解析限制。库名或栈顶只是故障位置，不是库缺陷的证明。
- **GPU 错误**：关联应用调用、kernel/数据规模与设备日志。MACA 日志出现 kernel trap、`traping: kernel name:` 或异常 `debug info` 时，使用 [kernel-trap-analysis](../kernel-trap-analysis/SKILL.md) 选择匹配 SDK 工具并定位设备指令/源码范围。区分错误被报告的位置和可能的首次触发位置。新增检查或同步只用于独立诊断，不覆盖原运行方式，不将其改变后的时序当作原始证据。
- **卡死/超时**：保留一段时间内的进展和多次状态观测，区分计算较慢、锁/通信等待、设备无进展及输入等待。MPI/多进程任务对齐 rank、时间与调用次序，不只检查一个进程。
- **资源或外部终止**：在可读范围核对容器退出信息、内存/显存使用及任务超时策略。不能仅凭退出 137、显存高或日志缺失断定 OOM。

缩小线程、rank、输入规模或功能开关时，一次改变一个相关条件并记录是否仍匹配原故障。debug/sanitizer、串行化或调试构建可能改变现象；未触发不证明原程序安全。工具缺失时保留证据缺口，不伪造报告。

若已有正常版本，按需叠加 [回退对照](../regression-analysis/SKILL.md)；没有正常版本照常进行上述诊断。缩小后发现数据错误可转 [正确性分析](../correctness-analysis/SKILL.md)，发现加载问题可转 [构建与运行启用](../build-runtime-analysis/SKILL.md)。

## 操作与交付边界

只调试本任务进程；附加调试器可能暂停进程，先确认目标身份和许可。core/内存转储可能含敏感数据，只留在受限目录，不直接上传 Jira。不得修改宿主全局 core 策略、复位 GPU 或终止他人作业。需终止自己的失控实验时核对精确目标，并保留退出结果。

交付故障签名、条件/频率、有效栈或等待证据、最小案例与原案的关系、候选责任和未排除项。仅绕过崩溃不称修复；候选修复须以原命令/数据复验。

GDB 的单次 `bt` 默认只覆盖当前线程；需要多线程证据时使用对应的全线程回溯能力，见 [GDB 官方文档](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Backtrace.html)。该 CPU 调试能力不代表当前工具能解析 GPU 内核。
