# 区分编译器、运行库与应用因素

编译器可在应用构建时生成代码，也可由 OpenCL/JIT 在启动或调优时调用。“应用二进制相同”不能排除 compiler 变化；“只换 UMD 目录”也可能同时替换它调用的 compiler。

## 对照

先确认源代码/内核、编译选项、目标架构、驱动与运行库身份。

| 变量 | 对照原则 | 查证身份 |
|---|---|---|
| AOT compiler | 同源同选项分别构建，在同一兼容环境运行 | 编译命令、compiler/产物 SHA-256 |
| UMD/运行库 | 同一产物，只变更兼容运行闭包 | loader 或 `/proc/<pid>/maps`、库 SHA-256 |
| OpenCL/JIT compiler | 同源同运行时，只变更实际调用的 compiler 闭包，各自隔离缓存 | JIT 加载库/子进程、有效选项、输入内核及产物 |
| 编译选项/调优 | 只变更指定参数，记录实际生效值 | 编译日志、dispatch、工作规模和内核选择 |

整个 SDK 的升级不是只升级 compiler。逆向替换需兼容 ABI，无法构造时如实说明。通过跟踪或只读挂载查证路径，不修改宿主 SDK。

## 编译器生成代码的性能回退

受控对照指向编译器生成代码引起 GPU 执行性能回退时，按[编译器 kernel 回退定位](../skills/compiler-kernel-regression/SKILL.md)继续定位与准备复现材料。

## 缓存与计时

确认应用实际缓存位置和禁用选项。各工具链使用本任务缓存；首次编译、预热和稳态测量分开，不清理共享缓存。缓存命中可能使新的 compiler 根本未被调用。保存编译输入、选项、日志与产物，不只比较应用可执行文件。

## 运行期编译

出现 JIT、recompile 或编译缓存线索时，使用 [运行期重编译分析](../skills/runtime-recompile-analysis/SKILL.md) 核实真实编译事件、触发边界及其影响。不要用应用调试级别或未经当前版本确认的环境变量代替编译证据。

自动调优时记录 kernel、工作组、循环次数及正确性。参数变化可能来自 compiler 资源用量，也可能是调优状态不同；需进一步对照，不能隐藏变化。

## 机制证据

按线索比较设备指令、寄存器/私有内存、spill、occupancy、访存或 dispatch，解释性能变化并用原案验证预测。

结论只写已验证范围；一次恢复、版本不同或关闭慢路径，不足以证明编译器内部缺陷。结束条件按[实验决策与收敛](../SKILL.md#实验决策与收敛)执行。
