# HPC 回退诊断

回退可表现为性能下降、crash、卡死、计算错误或构建失败，并非只有性能问题。只有明确存在软件版本或配置变化，并且正常与异常条件具有可比性时，才进入本专项。仅有硬件型号或平台不同不构成版本回退，应先按性能问题确认原始差异。找不到可比正常条件时转回 [问题分析](../../SKILL.md) 的对应症状专项，不把旧版本缺失当作整单阻塞。

存在有效对照时，GPU SDK 的性能、卡死或正确性回退使用完整 [GPU SDK 回退分析](../gpu-sdk-regression-triage/SKILL.md)。编译/链接失败等用本节受控对照原则，结合 [构建与运行启用](../build-runtime-analysis/SKILL.md)，不套用不匹配的 GPU 运行流程。

## 可选对照与证据要求

按当前证据选择有区分力的对照，不要求逐项执行：

- 核对同条件原案例的正常/异常结果，可复用来源与条件已经确认的有效记录。性能保留指标方向、单位、预热和原始样本；其它现象保留故障签名、退出/进展、错误结果与触发频率。历史截图可提供线索，单凭截图不能证明当前差异来自哪一组件。
- 比较实际执行栈而不只比较 SDK 版本。记录变化项与固定项；兼容依赖需一起替换时说明变化集合，不把整组恢复误归为其中某个组件。
- 需要区分构建与运行因素时，分离应用产物、构建编译器和运行 UMD/库。兼容性不明或加载失败的组合不能用于排除候选。
- 双向替换是加强归因的一种方法，不是唯一前提。受控替换、独立案例、实际调用/加载记录或直接代码证据也可组合支持判断；说明排除了哪些替代解释，未验证的方向不推定通过。只能确认版本相关时不升级为组件因果定位；内部机制仍需直接支持该机制的证据。

OpenCL/JIT、GPU 编译器或生成代码差异时读 [编译与运行分离](../../references/compiler-runtime.md)。compiler、UMD、数学/通信库是按证据选择的候选，不是必须遍历的固定流程。

受控对照已指向 AOT compiler 造成运行性能回退时，交付前按该参考固定源码、编译选项和运行环境，分别使用正常与异常编译器重新编译对应产物并运行对照；定位受影响的具体 kernel，给出两组的调用次数、单次与累计耗时及其对端到端差异的贡献，同时保留该 kernel 实际执行的完整编译命令。编译方法可从已有镜像源码中的 Dockerfile 或构建脚本取得；受工具或权限限制无法完成重编译、kernel 定位或命令取证时说明缺口，结论只停留在已验证的组件层级。编译耗时本身变慢不套用 kernel 执行性能要求。

依照问题模块的[实验决策与收敛](../../SKILL.md#实验决策与收敛)，仅在当前定位目标仍缺少可由 profiling 区分的证据时，使用完整复用的 [trace-report](../trace-report/SKILL.md)，先明确采集结果会改变哪个判断。已达到用户要求的组件或阶段定位时，不为补齐全部内部机制自动采集 profiler。非性能回退优先使用栈、输出差异或构建日志等对应证据。带 profiler、强同步或额外日志的运行独立标记，不能直接替代原始端到端性能样本。

## UMD/运行时性能定位

受控对照指向 UMD/运行时时，不能停在组件归属。应在现有授权和工具范围内说明具体回退现象，并定位到能解释差异的最小外部 API 或调用集合；比较正常与异常条件下的调用次数、单次及累计耗时，以及对端到端回退的影响。区分调用与入队、同步等待、数据传输、设备执行和初始化；包含同步等待或前置依赖的计时，不能直接归为某个 API 的耗时。定位到 API 边界即可，不分析其内部实现。

如果可以直接从原案例缩减，并保持调用顺序、频率、数据依赖和同步关系，则附上最小复现；否则交付已经缩小的原案例，不为构造示例改变问题语义。

同时核对影响该路径的显式环境变量、SDK 默认配置及进程内实际生效值。发现候选配置时，保持工作负载不变，对比未设置与显式值；兼容条件允许时做正常/异常版本的正反对照，并回验原案例。配置翻转能够稳定翻转结果时可确认其为因果触发；关闭功能或恢复旧路径仍是规避，除非证据进一步解释了开启路径为何变慢。

源码、符号、跟踪能力或权限不足时，可以停在已证实的 API/调用类别或阶段层级，但要写明缺少的机制证据和下一项可区分实验，不推测具体内部 API、kernel 或源码行。结构化字段 summary、root_cause 和 evidence 应直接呈现已确认的 API/调用类别、配置及实际值、受影响阶段和耗时贡献，不只写在 REPORT.md 中。

## 结果

区分已复现、版本相关、组件因果定位、机制已解释。仅定位组件也可交付对应团队，但不声称具体编译 pass 已被证明；列出未排除的交互及进一步确认实验。

记录控制条件、变化项、实际加载身份、原始结果与结论，可沿用已有日志或摘要，不要求另建固定实验表。最小案例与原案例的关系需核对；不能以最小案例通过代替原案例修复验证。不跨组修改实现，也不把诊断恢复称为正式修复。
