# 编译器 kernel 性能回退定位

在[回退诊断](../regression-analysis/SKILL.md)已确认性能回退后，若证据指向 compiler 生成产物，或已找到回退 kernel、需要区分 compiler 与运行库因素，使用本专项。编译耗时、首次 JIT、缓存或 host 提交路径变慢不进入本专项；组件尚未分离时参考[编译器、运行库与应用因素](../../references/compiler-runtime.md)。

目标是定位能够解释主要性能差异的 kernel 或调用集合，关联源码/生成链和实际编译命令，并交付经过验证的独立复现材料。方法和实验顺序按已有证据、可靠性和成本选择。不分析或修改编译器内部实现。

## 确认编译器影响

正常组与异常组控制源码、输入、精度、有效编译选项、运行库、驱动、硬件、计时口径和资源条件，只改变目标编译器。记录变化项、固定项和编译器及产物身份；必要依赖无法安全拆分时，明确实际对照的组件集合，不把整组恢复归因于其中一个文件。

使用正常、异常编译器重新构建，隔离输出目录和任务缓存，从日志确认编译器实际被调用，运行前核对使用的是对应产物。先检查正确性，再比较性能。旧缓存命中、ABI 不兼容的混搭或整个 SDK/镜像变化，不能单独证明编译器因果。

对照期间保持测试脚本、输入和被测产物不变；需要调整时保留原记录，重新建立可比样本。

## 定位主要回退 kernel

根据所缺证据选择采集方法，优先复用适用的现有工具。C500 可按需使用 [trace-report](../trace-report/SKILL.md)，选用后遵循其采集和校验流程；使用其他获准方法或临时工具时，核对测量对象、计时范围及其对原运行的影响。未插桩的端到端样本与 profiling 样本分别保存。

围绕主要耗时差异比较正常、异常组的 kernel 完整原始符号、承载产物、调用次数、输入规模、launch 配置、单次与累计耗时，保留原始样本并检查重复测量的稳定性和噪声。多个 kernel 共同造成主要回退时覆盖这些贡献者；已定位范围不足以解释原现象时继续扩大调查，交付时说明剩余未解释差异。

具体 device kernel 的判断需要与其身份对应的设备执行时间证据。host callback、调用入口或包含同步等待的区间计时只能说明相应路径，不能直接当作该 kernel 的耗时。编译器对照与 profiling 应对应同一组产物；产物不同时，先核验目标设备代码一致，不能拼接不同实验得出具体 kernel 的因果结论。

结合端到端和阶段耗时评估贡献。多 stream、异步或重叠执行时看实际时间线，不能简单相加 kernel 时间。融合、拆分或名称变化时按输入、调用区域和计算语义匹配集合；调用次数、launch 配置或路径选择变化单独说明，不全部归为单个 kernel 的代码生成质量。

## 关联源码与产物

沿实测 kernel 身份核对承载产物和源码/生成链。承载产物可由设备记录或同一被测产物上的唯一静态匹配确认；源码映射可使用符号、调试信息、编译数据库或构建日志。记录已核验的源码路径、版本和文件摘要；模板与生成代码注明实际编译单元及定义或生成入口。无法唯一映射时说明候选和缺口，不按名称猜文件或行号。

为补充符号而重建的产物仅用于辅助映射；若代码生成发生变化，不能替代原性能样本。静态映射也不能替代设备计时证据。

## 保留实际编译命令

取得生成目标设备代码的完整命令，不能只给顶层 `make`、`cmake --build` 或 Dockerfile 示例。说明命令来自实际构建日志、获准的进程记录、已核对目标与参数的编译数据库，还是尚未执行的还原结果，不把推测命令写成实测。

保留工作目录、编译器路径与版本、完整参数、输入输出、目标架构、宏与包含路径，以及影响编译的必要环境。参数文件需保留有效内容，输入源码和产物需能核对身份。使用 wrapper、LTO 或 device link 时，补齐实际执行编译或最终生成设备代码的命令。命令中的凭据脱敏。

JIT/OpenCL 场景记录实际编译输入、有效选项、编译器及必要依赖、缓存/产物和触发命令，说明对应的生成过程。

## 准备独立最小复现

依据已确认的回退 kernel、调用集合或触发条件，选择最直接的方式编写或提取小程序，可复用现有单测、算子或 kernel 代码。覆盖能够解释主要回退的执行范围；只复现部分问题时说明覆盖范围及剩余差异，不把局部结果当作完整解释。

小程序可以依赖必要的 SDK、库或框架，但应脱离完整原应用独立运行，不以文件数量或语言判断是否独立。仍需完整原应用运行、仅缩短步数或减小数据量的案例，只作为补充交接材料。

保留影响原现象的输入、精度、布局、编译选项、launch 和同步关系。分别用正常、异常编译器构建并运行，检查正确性，确认同向性能差异稳定且高于测量噪声；幅度不要求与原案例相同。报告区分单个 kernel 与组合路径的计时，准备工作和同步等待不能混入目标 kernel 的设备耗时。

用证据说明小程序与原问题中已确认的回退项和触发条件的联系。仅在合成输入中观察到编译器性能差异、尚未建立联系时，作为诊断线索交付，不能称为原问题的有效最小复现。可使用当前获准环境中已核验的等价工作负载，不要求报告者的原机器。

抽取后未复现时，对照原案检查遗漏的触发条件并调整验证。继续或停止按下述公共收敛要求判断；保留实际尝试，不能为制造差异改变问题语义。最小复现结果不能替代原案例回验。

## 交付与结束

在 `REPORT.md` 中说明主要回退范围和耗时影响、源码与编译命令的依据、最小复现验证结果、剩余差异和具体限制。按[网站交付规范](../../../jira-evidence/references/result-delivery.md)记录分析路径并逐文件交付报告、命令、必要证据和复现程序。

结束条件统一按[实验决策与收敛](../../SKILL.md#实验决策与收敛)和[外组交接](../../SKILL.md#外组交接)执行。尚未达到任务要求时，组件归属或调用路径只是阶段结论；仍有基于证据、获准且可执行的动作就继续。确因工具、源码、权限或必要输入限制无法推进时，交付已验证结论、真实尝试和具体缺口，不宣称已完成受阻的 kernel 定位或独立复现。
