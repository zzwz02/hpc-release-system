# 计算正确性分析

先确认“正确”的依据：原测试断言、发布测试、明确算法性质、可信参考输出或用户确认的容差。没有判据时可定位可观察差异、检查一致性或不变量，但不能自设标准宣称正确。基准或容差经查找仍缺失时，按[总入口规则](../../../../SKILL.md#缺失条件的处理)在报告和结构化结论中标明正确性验收未验证，由网站按本轮设置发布 Jira 评论，不交互追问。

## MACA 平台优先检查 shuffle / warp size

MACA 上出现计算错误，尤其是 CUDA 移植后结果不一致时，**优先检查相关 kernel 是否使用 `shfl` 或依赖 CUDA 的 32-lane warp 假设**，再选择后续区分实验。CUDA warp 为 32 线程，C500 硬件 wave 为 64 线程；具体 MACA 目标仍需核对实际设备、编译目标及 `warpSize`。区分硬件执行宽度和算法的逻辑 warp/tile 宽度，不能把所有 `32` 机械改成 `64`。

先搜索相关源码、封装和生成的 kernel：

```bash
rg -n -i 'shfl|warp|wave|ballot|activemask|syncwarp|tiled_partition|coalesced_group|0xffffffff|0x1f|0x3f' '<相关源码或生成 kernel 目录>'
```

继续检查宏展开、模板参数、JIT 生成代码和实际使用的 SDK/cu-bridge 实现；只在应用源码中搜不到 `__shfl` 不能排除该问题。重点核对：

- **Shuffle 分组**：`__shfl*` / `__shfl*_sync` 的默认或显式 `width`、源 lane、delta/XOR 范围是否符合算法分组。保留逻辑 warp32 时，应确认上、下两个 32-lane 子组分别交换数据；全 wave64 协作时则需覆盖 64 个 lane。不能仅凭 `0xffffffff` 就认定交换范围是 32；依赖兼容行为时核对当前 SDK 的具体实现。
- **Mask 与投票结果**：核对 `__ballot_sync`、`__activemask` 及 wrapper 的实际类型。全 wave64 路径需避免 mask/返回值在参数、局部变量或返回值中截断成 32 位，并检查 `1U << lane`、popcount/ffs 等操作的位宽。逻辑 warp32 使用投票结果时，应先按所在子组选取对应位段，再转换类型。
- **Lane 编号与归约**：检查 `& 31`、`>> 5`、`/ 32`、`% 32`、归约从 offset 16 开始/固定五轮、每 warp 临时存储大小、warp 数量和写回线程条件。确认这些常量描述的是逻辑 tile 还是硬件 wave，避免遗漏高 32 lane、跨子组混算或重复写回；同时检查 CUB/cooperative groups 的逻辑分组参数。
- **参与线程与同步**：检查尾块、条件分支和提前返回后，shuffle 的源 lane 是否有效、参与集合是否符合调用约定，以及 shared-memory 交换所需同步是否保留。不能用全满 mask 或“同一 warp 自然同步”的假设掩盖参与线程不足和同步缺失。

有命中时，用区分上下半 wave 的输入检查 lane 31/32、63 边界，覆盖两个逻辑 warp32 同处一个 wave64、非整 warp 工作量和相关分支；跟踪交换/归约前后的首个错误值。根据证据选择保留逻辑 warp32 或一致地适配 wave64，回到原案例和原判据验证。仅出现 `shfl` 或平台间 warp size 不同不能直接确定根因；记录检查结果后继续下述分析，具体平台语义按需读取[移植检查](../../../application-analysis/skills/maca-porting-checkup/SKILL.md)。

## 对齐输入与比较口径

核对数据内容/哈希、规模、精度、布局、算法选项、随机种子、预处理和设备/rank 配置。输出排序、单位、归一化和转换方式需一致。CPU、另一个 GPU 或旧版本的结果可以作交叉证据，不能未经验证自动成为真值。

比较整数/离散结果、浮点误差和随机/迭代算法时使用其原判据。记录失败元素/首个差异位置、实际值、期望值、误差口径与分布；区分正常容差内变化、误差超限、NaN/Inf、输出缺失。不得通过放宽阈值、过滤异常样本或降低工作量使测试通过。

## 选择区分实验

- 从输入到中间结果再到输出缩小首个偏差；若采集会改变时序或内存行为，单独标记诊断运行。
- 固定 seed 并重复同一原案例，观察是否稳定；单次通过不能排除竞态、未初始化或随机失败，也不能据不稳定性直接确认竞态。
- 按线索核对越界、生命周期、同步、精度转换、归约顺序和算法分支；独立探针须保留导致原案差异的条件。
- 工具链/选项变化作为候选：debug、禁用某优化或更换编译器导致恢复，只能先说明相关性；还需排除源码未定义行为及其它变量。有可比版本再叠加 [回退诊断](../regression-analysis/SKILL.md)。

崩溃或无进展转 [crash-analysis](../crash-analysis/SKILL.md)。保留原始失败输入与参考，不覆盖 golden 文件。

## 交付与验证

给出判据来源、可重复差异、有效定位实验、候选机制及未知项。未经正确性验证不进入性能优化；最小案例通过后必须回到原案例，并覆盖相关边界输入，才能按已有判据宣称候选修复有效。

内存、竞争与同步检查是不同证据，不能混为一项工具“已检查全部正确性”。[CUDA Compute Sanitizer 官方说明](https://docs.nvidia.com/cuda/compute-sanitizer/index.html) 体现了这种区分；它是 CUDA 工具，不能据此假定在 MACA 上可用。实际工具按现场支持能力选择，没有对应工具不阻止其它有效诊断。
