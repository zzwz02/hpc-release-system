# MACA 移植体检与 Jira 阶段的关系

完整保留原 Skill 的能力模型、GPU 使用地图、build/link/runtime/correctness 分类、兼容语义判断、0–9 章报告及命令。当前员工按模式使用，不把一个领域 Skill 变成不受约束的总调度。

| 模式 | 输入 | 允许产出 | 不允许混淆 |
|---|---|---|---|
| 原始复现 | 冻结命令/输入/oracle、精确环境 | 原始失败日志及匹配证据 | wrapper、SDK 或源码改动不能冒充原始 case |
| 只读体检/诊断 | 原始证据、源码位置、SDK/头文件访问权 | 支持/缺口表、失败层、候选假设、独立探针 | CUDA 名称/版本差异不是归属证据 |
| 获准候选适配 | HPC 所有权证据、批准可改路径、候选工作区 | 最小 patch、构建日志、候选测试 | 不改外组 SDK/compiler/driver 源码，不擅自升级共享环境 |
| 原始验收 | 候选构建、原始 case 身份 | 原测试结果与回归结果 | 最小 case PASS 不能替代原始 case PASS |

记录发现与支持依据、相关反例和未确认项；需要继续区分时再安排实验，不为每个发现填固定字段。若落在 compiler/UMD/通信/ACL，按 Jira 交付规范整理现有可复核方法和组件证据；最小化有助于判断或接手时再缩小案例，不以必须生成最小 case 延迟已有有效结果的交付，不跨组修复。

warp32/wave64、cooperative group、异步生命周期、原子循环和 fallback 路线按主文档判断。静态推断与实测分开；没有实际 SDK/设备时报告 `NOT_VERIFIED`，不能拿 CPU 合成测试当 GPU 证据。

完整移植体检任务可采用主文档的报告结构；仅借用其中一项诊断能力时，结果并入本工单报告，不额外生成 0–9 章报告。agent 按统一结果交付规范将必要依据和复核方法写入报告及结构化结论，由网站按本轮设置发布 Jira 评论，不以本地路径代替交付。来源中 AUTO_SAFE 是语义风险标签，不是自动修改授权。
