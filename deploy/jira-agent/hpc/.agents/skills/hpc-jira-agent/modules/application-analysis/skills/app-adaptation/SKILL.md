# HPC 应用适配

先确认目标平台/版本、应用源码身份、需要启用的功能、原或发布测试、正确性依据以及本次允许修改的范围。性能目标只在任务要求时确认，不把“能运行”默认扩展成全面优化。材料中的验收目标或标准不明确时，按[总入口规则](../../../../SKILL.md#缺失条件的处理)将影响写入报告和结构化结论，由网站按本轮设置发布 Jira 评论；继续推进已明确范围，不交互追问，也不自行补一个较低标准。

## 复用与推进

- 按问题选用 [hpc-opt-skill](../hpc-opt-skill/SKILL.md) 的适配方法或 [maca-porting-checkup](../maca-porting-checkup/SKILL.md) 核对构建/链接、GPU 接口与语义缺口，不要求两项都调用。已有镜像或目标平台版本可核对后复用，不要求从零移植。
- 需要应用专属知识时，按[应用模块导航](../../SKILL.md#按任务选择)选择实际可用的专项；其他应用使用通用方法，仅在知识缺口影响判断时说明限制。
- 在独立候选目录实施获准的最小变更，保持源码版本、构建选项与依赖可追溯。基于实际编译或测试反馈选择下一改动；映射名称相近的 API 不能代替语义验证。
- 按目标案例验证候选构建和正确性；要求性能时再选用 [性能分析](../../../problem-analysis/skills/performance-analysis/SKILL.md)。保留未支持功能与 fallback 限制，不通过关闭必要功能宣称全面适配完成。

新平台还没有可运行版本时，建立构建/验证基线即可开始，不要求构造历史 good/bad。过程中遇到构建失败、crash、卡死或数值差异，转 [问题分析](../../../problem-analysis/SKILL.md) 的匹配专项，取得结论后返回本次适配；这些都是同一会话内的方法选择。

## 交付与范围

交付源码/环境身份、变更、构建命令、已通过的目标案例、未支持项及需要人工确认的限制。最小探针通过不能替代应用目标案例。只有分析授权时交付兼容性判断和适配建议，不修改源码；允许本组适配也不等于允许修改外组 SDK、推送远端或变更共享环境。
