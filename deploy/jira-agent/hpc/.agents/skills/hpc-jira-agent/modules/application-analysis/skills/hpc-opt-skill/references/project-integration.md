# HPC 适配/优化领域子入口

本组件供当前员工在诊断、修复或验证阶段使用，总 Jira 调度和执行者交接由组合入口控制。

## 条件路由

1. 正确性未通过：禁止性能优化。编译/运行启用问题读取 adaptation；数值/crash 根因由对应诊断 Skill 先处理。
2. 已确认性能问题且有同条件 baseline：读取 optimization，核对独占租约、warmup/repetitions、单位/统计口径、噪声和同步点，再安排剖析。
3. APP 明确时按[应用模块导航](../../../SKILL.md#按任务选择)选择专属 Skill；未提供专项时使用通用方法，仅在知识缺口影响判断时说明限制。

## 条件依赖清单

| 依赖组件 | 当前状态 | 用途或缺失时处理 |
|---|---|---|
| maca-porting-checkup | 包内可用 | 用于 MACA 兼容体检，不自动覆盖原始复现 |
| [trace-report](../../../../problem-analysis/skills/trace-report/SKILL.md) | 包内可用 | 按需采集和解释 profiling，不替代原案例基准 |
| maca_operator_skill | 包内未提供 | 只提出有当前证据的通用候选，不伪造规则 |
| [应用专项](../../../SKILL.md#按任务选择) | 以模块导航为准 | 仅在应用匹配时使用 |
| maca_skill_evolver | 包内未提供 | 生成复盘建议，等待评估审核，不直接更新正式 Skill |

性能回退要做受控 A/B：固定原应用/数据/编译命令/机器/驱动，只改变一个候选维度；比较旧/新镜像只证明镜像组合有差异，不能直接锁定 compiler 或通信库。profiling 强制同步的时间不作为原端到端性能。

每轮记录待区分的问题、实际变化、有效结果及其对判断的影响；已有记录可复用，不要求每轮都改代码、重新构建或跑基准。是否追加实验按总入口的任务目标与证据缺口决定。尚未达到目标时如实说明已完成范围和限制，不宣称闭环。
