# 转交与人工接手材料

交接材料的目标是让接手的人（目标组或本组人工）不必重复前面的分析。

## 1. 整理 `artifacts/handoff.md`

使用以下结构：

```markdown
# <JIRA-KEY> 交接材料

## 结论
- 建议处理方：<目标组 / HPC 组人工>
- 原因：<一句话>

## 判断依据
- <证据 1：代码位置 / 日志行 / 复现结果>
- <证据 2>

## 复现方法
- 机器与环境：<机器、GPU、驱动与工具链版本>
- 步骤：
  1. <命令>
  2. <命令>
- 实际结果：<关键输出、退出码>
- 期望结果：<工单要求>

## 已排除的可能
- <已验证不是某个原因，以及依据>

## 关键日志
- artifacts/logs/<file>.log：<说明>

## 尚未确认 / 建议下一步
- <还需要谁、确认什么>
```

## 2. 要求

- 所有复现命令都必须是实际执行过的；未执行的写明“未执行”及原因。
- 关键日志保存到 `artifacts/logs/`，只保留和问题相关的片段或完整小日志，不要上传大体积构建产物。
- 不修改其他组负责的组件；如果做过验证性质的临时改动，写明改动内容并说明仅用于定位。
- 结论选择：
  - 明确属于其他组 → `not_our_group`，`ownership.target_group` 填目标组。
  - 归属不清或本组暂时处理不了 → `needs_help`，说明需要什么帮助。
  - 缺少信息 → `needs_info`，列出需要补充的具体信息。
- `artifacts` 中列出 `artifacts/handoff.md` 和相关日志。
